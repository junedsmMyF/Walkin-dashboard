# CLAUDE.md — Walk-in dashboard

Frido Founders Office dashboard. Owner: Abdal (AVP Founders Office). Deployed from GitHub `junedsmMyF/Walkin-dashboard` to Cloudflare Workers (Workers Builds, `main`).

- `src/index.js` — routes, admin, cron (06:00 IST). `src/bigin.js` — Bigin over MCP (Zoho `ZohoMCP_executeTool`, COQL on `Pipelines`, walk-in pipeline id `1371203000000480122`, 2,000 per page, `order by id`). `src/metrics.js` — all metric rules. `src/stores.js` — store master.
- `public/index.html` — single-file dashboard (hash routing). Reads `/api/metrics` only. Frido brand: #FFD100 / #101820, secondary #307FE2 #6CACE4 #DDE5ED #333F48, positive #80E0A7, alert #FF585D.
- Never change a metric rule without the owner's sign-off. Never send phone numbers or names to the browser. Never commit real customer data.
- Walk-in pages follow the original design boards (the Design flow tab was removed on request). Cards without a data source stay in place with an "Awaiting data source" state — never hide or fake them.
- The at-risk table shows Bigin lead IDs, store, owner account, product and value only — never customer names or phones.
- (Superseded) KPIs without a data source stay hidden (SLA trend, call attempts, escalations, capture point).
- Leads with no mappable store (e.g. owner is a person, Store Location empty) are kept in totals and excluded from store-level views.
- Store format: 16 Mall, 7 High street (in `src/stores.js`); rank each format separately.
- Sales source = BigQuery via apps-script/SalesToDashboard.gs (Apps Script as the user, daily 08:00 IST, last 7 days) → POST /admin/ingest-sales → KV monthly gzip blocks sales:m:YYYY-MM + sales:index → src/clean.js. Metrics cached in KV (metrics:cache). Gross = qty×price; revenue = gross − discount; keep cancelled/refunded. No service account. Never print or commit customer data (public repo).
- Open items: DSR names for FRIDO_0022–0025; stage-history (Bigin DealHistory) not yet used.

## PDP inventories (added Oct 2026)
- `src/pdp.js` + `/api/pdp` (perm `pdp`). Call route = Bigin **Callback Requests** pipeline (`CALLBACK_PIPELINE_ID` 1371203000000629516, website Call Store pop-up), stored in KV `bigin:callback` by the same daily refresh. Revenue = same BigQuery sales, phone match, order **on/after** lead date (pending sign-off). Starts `PDP_START_DATE` 2026-10-08.
- Text route = **real LimeChat export** read live from secret `LIMECHAT_CSV_URL` (published CSV; holds customer phones/names — never put the link in this public repo). `src/limechat.js` rebuilds each ticket's stage from hand-off + First Assignee + agent message + Private Notes; **Ticket Status is ticket state, not a lead stage** (kept as raw only). Notes are standardised by `NOTE_RULES`; raw values always kept; hygiene issues flagged, never fixed in place. Order matched to both a call and a WhatsApp lead → credited to the earlier lead (pending sign-off).
- PDP views / CTA clicks / Call Store pop-up opens are still **sample** (`buildSample`) until GA4/Shopify is connected — keep the Sample badge.
- Website store labels (Store_Name1) map via `WEB_STORE_ALIASES` in `src/pdp.js`.
- Bigin refresh reads up to 45 × 200 = 9,000 Pipelines records per run (6,728 on 13 Oct 2026) — raise the cap or filter by pipeline before it is hit.
- Backend agent = Bigin owner / LimeChat first assignee. Final flow = Whimsical K8YnGdgbNtixDZnFj3vHtF (updated 21 Oct 2026). After "Qualified?": routing via agent on the WhatsApp DSR group → store visit, bill by store staff; or video consult with the store team → order placed by the store team. The "order punched by backend agent" branch was removed. Conversion route (pending sign-off): ONLINE punch-in → **video**; else **store**.
- **Consumed** (replaces "agent assigned" in the funnel — every lead is assigned): call = Bigin stage past Yet to Call (`cons`); WhatsApp = agent replied (First Agent Message Time or Agent Message Blocks > 0). A call note without a reply is shown separately ("call note, no reply"), not counted. No agent-assignment KPIs anywhere (every lead is assigned): bot-only / handed-off / assigned-no-action are one bucket, "Not picked up"; assignment hygiene flags stay in the data but are hidden.
- LimeChat export format changed in Oct 2026 (ISO `YYYY-MM-DD HH:MM:SS`, True/False). `lcTime` accepts both formats — check new exports against it.
- Stores & cities page removed (Oct 2026). Store analysis lives on Revenue → "Store visits & video consults by store": visits scheduled (routing sheet), visited & bought (billed at that store), no-show, store-visit vs video-consult orders, revenue, share of store sales — grouped by city.
- CTA performance: click a CTA row to expand it (`F.ex`) — Call Store and Chat with store by store, PDP chat by product. Store visits card: click a city row to expand its stores (`F.cx`). No grouping toggles (owner request).
- Store routing = "Lead routing backend" Google Sheet, filled automatically from the WhatsApp DSR groups, read live from secret `ROUTING_CSV_URL` (customer names/phones — never commit). `src/routing.js` standardises it (US M/D/YYYY dates, visit-time slots, "NM - " category prefix) and flags test rows (name "test" or a phone used on a test row), repeat phones, unmapped stores, missing slots. Routed → billed = DevX order on/after the routing date, same phone, any store. Video consults are not logged anywhere yet (Not tracked).
- Entry point → revenue (story chapter 2 + Revenue tab): Call = Call Store pop-up; WhatsApp = LimeChat Level 1 tag (PDP chat, store widget, store card, store inquiry, generic). Revenue uses the deduped order list (earlier lead wins), so entry totals equal PDP revenue.
- PDP pages have a global **CTA toggle** (`F.cta`: all · call_popup · store_card · store_widget · pdp · store_inquiry · generic) applied in callAgg/textAgg/allAttributed/routeAgg; the CTA performance card always compares all CTAs. Get Direction is not a lead CTA — removed everywhere.
- Customer journey page (exec layout, Oct 2026): story band → 5 KPIs → lead funnel → CTA performance → how qualified leads convert + what to fix → stage-by-stage detail (collapsed toggle, full call-vs-WhatsApp chapters in Whimsical order).
- Lead funnel (Oct 2026): PDP → lead capture → consumed → connected → qualified → conversion outcome (converted / lost / open). Store visit and video consultation are **routing outside the funnel**, never a funnel stage.
